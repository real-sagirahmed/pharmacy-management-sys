## ১. নির্বাহী সারসংক্ষেপ (Executive Summary)

[s7PMS-guide-lines.md](file:///d:/s7PMS/Guidelines/s7PMS-guide-lines.md) ডকুমেন্টে বাংলাদেশের ফার্মেসি ব্যবসায়ের বাস্তব প্রেক্ষাপট, সমস্যাসমূহ (যেমন: এক্সপায়ারি অপচয়, ম্যানুয়াল বিলিং ত্রুটি, ডিজিডিএ অডিট, বাকির খাতা, লোডশেডিং/ইন্টারনেট বিভ্রাট) এবং একটি আদর্শ সিস্টেমের বৈশিষ্ট্যসমূহ তুলে ধরা হয়েছে।

এই ডকুমেন্টের উদ্দেশ্য হলো:
1. বর্তমান কোডবেসে **কি কি ইতিমধ্যেই সম্পন্ন হয়েছে** তা স্পষ্ট করা।
2. গাইডলাইনের সাপেক্ষে সিস্টেমে **কি কি গুরুতর গ্যাপ** রয়েছে তা চিহ্নিত করা।
3. উক্ত গ্যাপগুলো **কিভাবে কারিগরিভাবে পূরণ করা হবে** তার নিখুঁত ইঞ্জিনিয়ারিং প্ল্যান দেওয়া।
4. ওভার-ইঞ্জিনিয়ারিং এড়িয়ে **বর্তমানে (Immediate)** এবং **ভবিষ্যতে (Future)** কি কি যোগ করা হবে তার পর্যায়ক্রমিক রোডম্যাপ নির্ধারণ করা।

## ২. বর্তমানে যা যা সম্পন্ন হয়েছে (Completed Features & Architecture)

## ৩. কাজের গ্যাপ বিশ্লেষণ (Identified Gaps)

গাইডলাইনের ব্যবসায়িক ও কমপ্লায়েন্স রিকোয়ারমেন্টের সাথে বর্তমান কোডবেসের তুলনামূলক ব্যবধান নিচে তুলে ধরা হলো:

| ক্রম | গ্যাপের নাম | গাইডলাইনের প্রত্যাশা | বর্তমান অবস্থা | ঝুঁকির মাত্রা |
| :---: | :--- | :--- | :--- | :---: |
| **১** | **ব্যাচ-লেভেল স্টক লেজার (FIFO)** | প্রতি ব্যাচের আলাদা ব্যালেন্স থাকতে হবে; পুরানো ব্যাচ আগে বিক্রি হবে। | স্টকে শুধুমাত্র মোট `StockQuantity` সেভ হয়; ব্যাচ ভিত্তিক স্টক ব্যালেন্স আলাদা টেবিলে নেই। | **উচ্চ (Critical)** |
| **২** | **মেয়াদোত্তীর্ণ ব্যাচ ব্লকিং (POS Lock)** | মেয়াদ শেষ হওয়া বা রিকল হওয়া ব্যাচ বিলে অ্যাড হওয়া সম্পূর্ণ ব্লক থাকবে। | এক্সপায়ারি রিপোর্ট আছে, কিন্তু পিওএস কার্টে যোগ করার সময় হার্ড ব্যাকএন্ড ভ্যালিডেশন নেই। | **উচ্চ (Critical)** |

| **৫** | **প্রেসক্রিপশন ইমেজ ও অডিট রেকর্ড** | অ্যান্টিবায়োটিক ও রেস্ট্রিক্টেড ওষুধের প্রেসক্রিপশন ছবি সংরক্ষণ। | বিলে প্রেসক্রিপশন ফাইল আপলোড বা লিংকের ফিল্ড নেই। | **মাঝারি (Medium)** |
| **৬** | **মাল্টি-ব্রাঞ্চ আর্কিটেকচার** | একাধিক শাখার স্টক সেন্ট্রালি দেখা ও ব্রাঞ্চ ট্রান্সফার। | সম্পূর্ণ সিঙ্গেল-স্টোর আর্কিটেকচার; কোনো `BranchId` নেই। | **ভবিষ্যতের জন্য** |

| **৮** | **অটোমেটেড এসএমএস রিফিল অ্যালার্ট** | দীর্ঘমেয়াদী রোগীদের (ডায়াবেটিস/প্রেসার) অটো রিফিল এসএমএস। | কোনো এসএমএস গেটওয়ে সার্ভিস যুক্ত নেই। | **ভবিষ্যতের জন্য** |

## ৪. গ্যাপগুলো যেভাবে কারিগরিভাবে পূরণ করা যাবে (Technical Remediation Plan)

### ৪.১ ব্যাচ-লেভেল স্টক ট্র্যাকিং (Batch Inventory Normalization)
- **সমস্যা:** বর্তমানে `Medicines` টেবিলে একটাই `StockQuantity` ফিল্ড আছে। ফলে এক মেডিসিনের একাধিক ব্যাচ আসলে কোন ব্যাচে কত পিস অবশিষ্ট আছে তা আলাদাভাবে ট্র্যাক করা যায় না।
- **সমাধান:** 
  - একটি নতুন টেবিল `MedicineBatches` প্রবর্তন করা:
    ```csharp
    public class MedicineBatch
    {
        public int Id { get; set; }
        public int MedicineId { get; set; }
        public string BatchNumber { get; set; } = string.Empty;
        public DateTime ExpiryDate { get; set; }
        public int CurrentStock { get; set; }
        public decimal PurchasePrice { get; set; }
        public decimal SalePrice { get; set; }
        public string Status { get; set; } = "Active"; // Active, Recalled, Expired
    }
    ```
  - প্রতিটি পারচেজে সংশ্লিষ্ট ব্যাচে স্টক বৃদ্ধি পাবে এবং পিওএস সেলসে স্বয়ংক্রিয়ভাবে নিকটতম মেয়াদের ব্যাচ থেকে (FIFO নীতিতে) স্টক কমবে।

### ৪.২ পিওএস এক্সপায়ারি ও ডিজিডিএ রিকল গার্ড (POS Hard-Validation)
- **সমস্যা:** ক্যাশিয়ার ভুলবশত মেয়াদোত্তীর্ণ বা রিকল হওয়া ব্যাচ স্ক্যান করে বিক্রি করতে পারে।
- **সমাধান:**
  - `SalesController.cs`-এ বিল সেভ করার সময় ব্যাকএন্ড ইনভ্যারিয়েন্ট ভ্যালিডেশন যুক্ত করা:
    ```csharp
    if (batch.ExpiryDate <= DateTime.Today)
        return BadRequest($"ব্যাচ {batch.BatchNumber}-এর মেয়াদ উত্তীর্ণ হয়েছে। এটি বিক্রি করা নিষিদ্ধ।");

    if (batch.Status == "Recalled")
        return BadRequest($"DGDA নির্দেশনায় ব্যাচ {batch.BatchNumber} রিকল করা হয়েছে।");
    ```

### ৪.৩ থার্মাল বাংলা প্রিন্টিং ইঞ্জিন (Bilingual POS Thermal Print)
- **সমস্যা:** ডিফল্ট প্রিন্টিংয়ে বাংলা অক্ষর ভেঙে যায় বা অস্বচ্ছ আসে।
- **সমাধান:**
  - ফ্রন্টএন্ডে ৮০মিমি থার্মাল লেআউটের জন্য ডেডিকেটেড লাইটওয়েট এইচটিএমএল/সিএসএস প্রিন্ট কম্পোনেন্ট তৈরি করা (`@media print` রুল দিয়ে)।
  - ইউনিভার্সাল বাংলা ফন্ট (যেমন `Kalpurush` বা `Noto Sans Bengali`) এমবেড করা।
  - ইনভয়েসের ফুটার অংশে দ্রুত ডিজিডিএ ড্রাগ লাইসেন্স নম্বর, কাস্টমার ডিউ সামারি এবং পেমেন্ট কিউআর কোড যুক্ত করা।

### ৪.৪ প্রেসক্রিপশন ক্যাপচার (Prescription Storage)
- **সমস্যা:** ডিজিডিএ অডিটে প্রেসক্রিপশন ছাড়া অ্যান্টিবায়োটিক বিক্রির অভিযোগ এলে প্রমাণ রাখা কঠিন।
- **সমাধান:**
  - `SalesMaster` টেবিলে `PrescriptionImagePath` এবং `DoctorName` ফিল্ড যুক্ত করা।
  - পিওএস স্ক্রিনে ওয়েবক্যাম বা মোবাইল দিয়ে সরাসরি প্রেসক্রিপশনের ছবি আপলোড করার সুবিধা রাখা।

## ৬. সলিউশন আর্কিটেক্টের পর্যবেক্ষণ (Architectural Governance)

1. **সিম্পলিসিটি বনাম জটিলতা:**  
   একক ফার্মেসি বা ২-৩ টি শাখার জন্য শুরুতেই ক্লাউড মাইক্রোসার্ভিস বা জটিল ডিস্ট্রিবিউটেড মেসেজ কিউ (RabbitMQ/Kafka) অপ্রয়োজনীয়। বর্তমান মনোলিথিক মডুলার আর্কিটেকচার (ASP.NET Core Web API + SQL Server) প্রতি সেকেন্ডে শত শত ইনভয়েস কোনো ল্যাগ ছাড়াই প্রসেস করতে সম্পূর্ণ সক্ষম।
2. **আর্কিটেকচারাল ডিসিশন লক (Architectural Lock):**  
   - ফিন্যান্সিয়াল ও স্টক ক্যালকুলেশন সর্বদা **ব্যাকএন্ড ডেটাবেজ ট্রানজেকশনে (`IDbContextTransaction`)** সম্পন্ন হতে হবে। ফ্রন্টএন্ড থেকে আসা কোনো টোটাল বা ব্যালেন্সকে বিশ্বাস করা যাবে না।
   - সব ডেটাবেজ টাইমিং **`Bangladesh Standard Time (UTC+6)`** অনুযায়ী লক থাকবে, যা ইতিমধ্যে কোডবেসে অনুসৃত হচ্ছে।

## ৭. উপসংহার ও পরবর্তী করণীয়

বর্তমান কোডবেসটি একটি কার্যকর ফার্মেসি পিওএস সিস্টেম হিসেবে চালু রয়েছে। এখন সবচেয়ে বুদ্ধিমানের কাজ হবে **Phase 1: Core Hardening**-এর কাজগুলো সম্পন্ন করা, যার মধ্যে রয়েছে **ব্যাচভিত্তিক স্টক ব্যালেন্স নিশ্চিতকরণ** এবং **মেয়াদোত্তীর্ণ ওষুধ বিক্রয় রোধে পিওএস ভ্যালিডেশন**। 

এই ডকুমেন্টটি টিমের জন্য একটি সুনির্দিষ্ট কারিগরি দিকনির্দেশনা (Technical Blueprint) হিসেবে কাজ করবে।
